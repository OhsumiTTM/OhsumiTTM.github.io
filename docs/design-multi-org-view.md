# 設計書: 兼部の統合表示(複数の団体のタスク・予定を1つの画面で見る。まだ作っていない)

この文書は設計だけです。コードはまだ書いていません。公開の後に作ることを前提にしています。
関係する調査: [docs/gas-change-forecast.md](gas-change-forecast.md) の 1-10(兼部の統合表示)。
団体の GAS の更新は、[design-record-rows.md](design-record-rows.md)(記録を1件1行のシートに移す)と1回にまとめる前提です。

- 作業量は、テスト・README を含めた目安です(1日 = 1人の作業日)。

## 0. まとめ

- **何を見せるか:** 複数の団体に入っている人(兼部)が、自分の担当・確認待ち・期限・予定を、団体をまたいで1つの画面で見られるようにします。
- **仕組み:** サーバーは足しません。
  - 端末に保存している **団体ごとのログイン(セッション)** で、**各団体の GAS に直接** 問い合わせます。
  - 答えは **画面の中でだけ** まとめます。どこにも送らず、端末にも保存しません。
- **団体の GAS に足すもの:** 読み取りの操作 `getMyDigest` を1つだけ足します。
  - 返すのは、本人の担当・確認待ち・期限・予定だけです。
  - ほかの人のデータ・団体の設定は返しません。
- **見る場所:** OUTPUT の「ホーム」の上に「すべての団体」の切り替えを置きます。
  - タスクを開く時・操作する時は、その団体に切り替えます(書き込みは、今と同じく今の団体でだけ行う)。
- **プライバシーポリシー:** FSIF に届く情報は増えません。端末に保存するものも増やさない設計にします。
  - そのため、**文言の変更は要らない見込み** です。ただし説明を1文足すことを勧めます(6)。
- **作業量:** 6〜8日(GAS 1.5〜2・画面 3.5〜4.5・テスト 1〜1.5)。

## 1. 今の仕組み(前提)

- **団体の一覧(`lib/ohsumi/org-directory.ts`):**
  - 端末の `localStorage` の `ohsumi-orgs` に、団体ID・接続先(その団体の GAS の URL)・団体名を持ちます。
  - 今使っている団体は `ohsumi-current-org` です。
  - 団体を切り替える時は、団体ごとの保存(`ORG_SCOPED_STORAGE_KEYS`)を消して、ページを読み込み直します。Google のログインの準備は1ページに1回のためです。
- **ログイン(`lib/ohsumi/session.ts`):**
  - セッションは **団体ごとに別のキー**(`ohsumi-session-<団体ID>`)で保存します。
  - 「この端末にログイン情報を保存する」がありなら `localStorage`(最長30日、ふだんは14日で延長)、なしなら `sessionStorage`(タブを閉じると消える。12時間)です。
  - **団体を切り替えても、ほかの団体のセッションは消えません。** 統合表示はこれを使います。
- **通信:**
  - 画面は団体の GAS(`script.google.com`)に直接 POST します(`gas-transport`)。
  - CSP の `connect-src` は、すでに `script.google.com` と `script.googleusercontent.com` を許しています(`scripts/csp.mjs`)。
  - 団体ごとに URL が違っても、同じ許可のままで送れます。
- **団体の GAS の読み取り:**
  - `getInitialData` は、団体のデータ全体(見てよい分)を返します。統合表示には大きすぎ、ほかの人のデータも含みます。
  - そのため、専用の小さな操作を足します。

## 2. 団体の GAS に足す読み取り: `getMyDigest`

### 2-1. 受け取るもの

```
{ action: 'getMyDigest', sessionToken, clientVersion, from: 'YYYY-MM-DD', to: 'YYYY-MM-DD', knownVersion? }
```

- **`from`〜`to`:** 予定・期限を返す期間です。最長62日にし、それより長い期間は断ります。
- **`knownVersion`:** 前に受け取った版です。データの版が同じなら `unchanged: true` だけを返します(今の `getInitialData` と同じ)。

### 2-2. 返すもの(本人に関係する分だけ)

```
{
  version, orgName, memberId, memberName, themeColor?,
  contract: { phase, kind },            // 機能停止・提供停止の状態(2-4)
  tasks: [ { id, title, status, dueDate?, dueTime?, startDate?, priority, importance,
             projectName?, role: 'assignee' | 'reviewTarget' | 'invitee', overdue: bool } ],
  schedules: [ { taskId, title, candidates: [{ id, label, date?, startTime?, endTime? }], answered: bool } ],
  counts: { assigned, reviewWaiting, overdue, unansweredSchedules },
  truncated?: bool
}
```

- **`tasks`:** 次の3つにあたる、ゴミ箱に無いタスクです。
  1. 本人が担当で、完了していない(`assignee`)
  2. 確認待ちで、本人が確認する人(`reviewTarget`)
     - 確認する人の判定は `reviewTargets_` と同じです(確認者 → 担当者の報告先 → 全権管理者)。
  3. 日程調整・フォームで、本人が招待されていて答えていない(`invitee`)
  - 上限は200件です。超えたら、期限の近い順に200件を返し、`truncated: true` を付けます。
- **`schedules`:** 本人が招待されている日程調整の候補です。期間の中の日付の候補だけを返します。
- **返す項目:** 件名・状態・日付・優先度・重要度・プロジェクト名だけです。
  - 説明・コメント・成果物・ほかの担当者・確認者の名前は **返しません**。統合表示では、一覧から「その団体で開く」までを受け持ちます。
- **見えるかどうか:** 必ず `canViewTaskRow_` を通します。今の画面で見えないタスクは返しません。
  - 例: 承認待ちのタスクは、作った人と担当者だけに返します。
- **返さないもの:**
  - ほかの人のタスク・メンバーの一覧
  - 団体の設定(役職・権限・通知の送り先など)
  - 人材の情報
  - 団体の設定のうち、`orgName` と `themeColor` だけは返します。統合表示で、団体の見分けに使います(4-2)。

### 2-3. GAS の中での作り方

- 今のスナップショット(`loadSnapshot_`。版ごとのキャッシュ)から作ります。シートを新しく読みません。
- 作った結果は、`版 + メンバーID + 期間` ごとに `CacheService` に5分置きます。続けて開いても重くなりません。
- **ログインの扱い:**
  - 今のセッションの確かめ(`06-auth-session.gs`)を通します。
  - セッションの延長は、`getInitialData` と同じく返事の `session` で返します。統合表示を開くだけでも、ログインが切れにくくなります。
- **権限の表:** `getMyDigest` は「読み取り」の操作として、権限の表(`38-capabilities.gs`)と、機能停止の時の読み取りの許可(`readOnlyAllows_`)に足します。
- **回数の上限:** `RATE_LIMITS` に `digest` を足します(1人1時間120回)。超えたら、前の版の答え(キャッシュ)を返します。
- **記録との関係:** [design-record-rows.md](design-record-rows.md) と同じ GAS の更新に入れます。
  - `getMyDigest` はコメントを読まないので、記録の持ち方(セルか行か)の影響を受けません。

### 2-4. 停止中の団体

- **提供停止中(`suspend`):** 今は、ログイン以外をすべて断っています。
  - `getMyDigest` も断り、`{ ok: false, suspended: true }` だけを返します。
  - 統合表示には「この団体は利用を停止しています」とだけ出します。
- **機能停止中(`restrict`。読み取りだけできる):** `getMyDigest` は読み取りなので返します。
  - `contract` で知らせ、統合表示に「この団体は読み取りだけです」と出します。

## 3. 画面での問い合わせ

### 3-1. 問い合わせる団体

- 端末の団体の一覧(`loadSavedOrgs()`)のうち、**有効なセッションがある団体だけ** に問い合わせます(`loadSession(orgId)` が期限内のもの)。
- 今の団体も含めます。ただし今の団体は、すでに読み込んでいるデータから同じ形を作ります(問い合わせない)。
- 上限は10団体です。それを超える団体は、最後に使った順で後ろの団体を「表示しない」にします。

### 3-2. 並列・待ち時間・キャッシュ

- 団体ごとの問い合わせは **並列** に送ります(各団体の GAS は別のスクリプトなので、互いに待たない)。同時に送るのは4つまでにします。
- 1つの団体の待ち時間は15秒までです。
  - 超えたら、その団体の欄に「応答がありません(再読み込み)」を出し、ほかの団体はそのまま出します。
  - 遅い団体を待って全体を出さない、ということはしません。
- **答えのキャッシュ:** 団体ごとの答えを **画面のメモリにだけ** 置きます(`localStorage` には置かない。6)。
  - 統合表示を開き直した時は、メモリの答えをすぐに出し、裏で `knownVersion` 付きで問い合わせます。
  - `unchanged` ならそのまま、変わっていれば差し替えます。
  - ページを読み込み直すと消えます。
- **問い合わせる時:**
  - 統合表示を開いた時
  - 開いている間は5分ごと(タブが見えている時だけ)
  - 「再読み込み」を押した時
  - ほかの画面を見ている時は問い合わせません。

### 3-3. ログインが切れている団体

- セッションが無い・期限切れ・GAS が「ログインし直してください」を返した時は、その団体の欄に「ログインが切れています」と「この団体に切り替えてログイン」を出します。
  - 押すと `switchToOrg(orgId)` で切り替えます。
- Google のログイン(IDトークン)は、1ページに1つの団体でしか準備できません。そのため、**統合表示の中で、ほかの団体にログインし直すことはしません**。
- 「この端末にログイン情報を保存する」を選ばずにログインした団体は、そのタブを閉じると切れます。
  - 統合表示の最初に「ほかの団体も、ログインを保存しておくと、ここに出ます」と案内します。

### 3-4. 古い GAS の団体

- `getMyDigest` を知らない古い GAS は「不明な操作」を返します。その団体の欄には、「この団体の Ohsumi が古いため、まとめて表示できません」と出します。
- 担当者への知らせは、今の「GAS の更新のお知らせ」(レジストリの版の判定)に任せます。統合表示からは出しません。

## 4. 画面の案

### 4-1. どこに出すか

- **OUTPUT の「ホーム」(ダッシュボード)の上に、切り替え「この団体 / すべての団体」を置きます。**
  - 端末に団体が2つ以上あり、2つ以上にログインしている時だけ出します。
  - ふつうの1団体の人には、何も変わりません。
- **「すべての団体」の中身:**
  1. **今日やること:** 期限が今日・過ぎているタスク(団体をまたいで期限の順)
  2. **確認待ち:** 本人が確認する人のタスク
  3. **予定:** 期間の中の期限・開始日と、答えていない日程調整の候補(週の表示。カレンダーの見た目に合わせる)
  4. **団体ごとの数:** 担当・確認待ち・期限切れ・未回答の数。応答がない・ログインが切れている・停止中の知らせもここに出す
- **ヘッダーの団体の切り替え(`org-switcher.tsx`):** 各団体の横に、期限切れ・確認待ちの数の小さな印を出します。統合表示を開いている時だけで、数はメモリの答えから作ります。

### 4-2. 団体の見分け方

- 各タスクの行の左に、**団体の色の帯と団体名の短い名前**(4文字まで。長い名前は省略して、全体は title で出す)を付けます。
- **色:** 団体のテーマの色(`themeColor`)を使います。
  - 同じ色・似た色の団体が並ぶ時は、2つ目以降を、決めた予備の色の並び(6色)から選びます。
  - 色だけで見分けさせないため、団体名の文字を必ず一緒に出します。
- **並べ方:** 「期限の順(団体をまたぐ)」と「団体ごと」を切り替えられます。前回の選択は端末に保存します(表示設定。6)。

### 4-3. 操作

- 統合表示では、**状態の変更・コメントなどの書き込みはしません。**
- タスクを押すと、「<団体名> で開く」で `switchToOrg(orgId)` に切り替えます。
  - 読み込み直した後に、そのタスクを開きます(`?org=<団体ID>&task=<タスクID>`)。
    - `task` の指定は今は無いので、画面に足します(読み込み直した後に1回だけ開き、アドレスバーからは消す)。
- 理由: 書き込みは、今の団体のデータ(行の版・権限・通知)を読み込んだ状態でしか正しく確かめられないからです。

### 4-4. 画面の幅

- 375px では、団体の名前の印を上の行、件名を下の行にします。
- `check:layout` に「すべての団体」(3団体、うち1つは応答なし・1つはログイン切れ)を足し、はみ出しと文字の折り返しを確かめます。

## 5. 安全

- **トークンは混ぜない:** 送る先(団体の GAS の URL)とセッショントークンは、必ず同じ団体のものを組にします。
  - `SavedOrg.gasUrl` と `ohsumi-session-<同じ団体ID>` だけを使います。
  - 接続先の URL の形(`CANONICAL_GAS_URL`)を確かめるのは、今と同じです。
- **GAS 側でも確かめる:**
  - セッショントークンには団体ID(`org`)が入り、団体ごとの鍵(`SESSION_SIGNING_KEY`)で署名しています。
    ほかの団体のトークンは署名が合わないので、今の仕組みのままで断られます。
  - ほかの団体のトークンを送られても断ります。
- **答えは端末に残さない:**
  - まとめた答えはメモリにだけ置き、ログアウト・ページの読み込み直しで消えます。
  - 共用の端末で、ほかの団体のタスクの件名が残らないようにします。
- **画面のエラーの記録:**
  - 統合表示のエラーを団体に送る時(`clientError`)は、エラーが起きたその団体の GAS にだけ送ります。
  - ほかの団体の名前・タスクの件名は含めません。

## 6. プライバシーポリシーへの影響

| 観点 | 変わるか | 理由 |
|---|---|---|
| FSIF が受け取る情報(第3項) | 変わらない | FSIF のサーバーを通らない。レジストリにも問い合わせない |
| 団体のデータの置き場所 | 変わらない | 各団体のスプレッドシートのまま。まとめるのは画面のメモリの中だけ |
| 端末に保存する情報(第4項) | **変えない設計** | まとめた答えは保存しない。端末に足すのは「並べ方の選択」(表示設定。今の「一覧の並び順や表示項目などの表示設定」に含まれる)だけ |
| 第三者への提供 | 変わらない | 団体Aのデータが団体Bに送られることはない(各団体の GAS には、その団体のトークンで、その団体のことだけを聞く) |

- **結論:** 文言の変更は要らない見込みです。
- **ただし勧めたいこと:** 第4項に、「複数の利用組織にログインしている場合、それぞれの利用組織から本人に関係するタスクの情報を読み込み、端末のメモリ上でまとめて表示します(保存はしません)」の1文を足すことを勧めます。
  - 兼部の人が「ほかの団体に見えているのでは」と心配しないようにするためです。
- 文言の最終判断は、契約書・規約の担当でお願いします(要確認)。

## 8. テストの計画

- **GAS の単体(`gas-guard-harness` に2人以上・承認待ち・幹部限定・ゴミ箱・日程調整のタスクを用意):**
  - 本人の担当・確認待ち・未回答の日程調整だけが返る
  - **ほかの人のタスク、説明・コメント、団体の設定、人材の情報が返らない**(返事のキーを全部並べて、許した一覧と比べる)
  - 承認待ちのタスクは、作った人と担当者だけに返る。ゴミ箱は返らない
  - 確認待ちの宛先が `reviewTargets_` と同じ(確認者 → 報告先 → 全権管理者)
  - 期間の上限(62日)・件数の上限(200件と `truncated`)
  - `knownVersion` で `unchanged`
  - 提供停止で断る・機能停止で返す
  - ほかの団体のトークンを断る
- **画面の単体:**
  - 有効なセッションの団体だけに問い合わせる
  - 同時に4つまで
  - 15秒で、その団体だけ「応答がありません」
  - ログイン切れ・古い GAS・停止中の表示
  - メモリのキャッシュと `unchanged`
  - ログアウトで答えが消える
  - トークンと接続先の組がずれない(団体Aのトークンを団体Bの URL に送らない)
- **`check:layout`:** 375px と広い画面の「すべての団体」(3団体・応答なし・ログイン切れ・色の重なり)。
- **通しテスト:**
  - テスト環境の団体とデモの団体の2つにログインした端末で、両方のタスクが出る
  - 押すとその団体に切り替わって開く
  - 片方を提供停止にすると、知らせが出る

## 9. 危険と対策

| 危険 | 起きること | 対策 |
|---|---|---|
| 返す項目が多すぎる | ほかの人の情報が別の団体の画面と一緒に見える | 返す項目を許した一覧だけにし、テストで返事のキーを固定する |
| トークンと接続先の取り違え | 団体Aのトークンが団体Bに送られる | 組を `SavedOrg` と同じ団体IDのセッションからだけ作る。GAS 側でも団体IDを確かめる |
| 多くの団体に問い合わせて遅い | ホームが重い | 並列4つ・15秒で区切る・メモリのキャッシュ・開いている時だけ問い合わせる |
| 団体の GAS の負荷 | 実行の回数が増える | 5分のキャッシュ・`unchanged`・1人1時間120回まで |
| 共用の端末に残る | ほかの人がほかの団体の件名を見る | 答えは保存しない。ログアウトで消える |
| 古い GAS の団体 | まとめに出ない | 「古いため表示できません」と出す。更新の案内はレジストリの仕組みに任せる |

## 10. 決めておきたいこと(要確認)

1. 統合表示の場所(ホームの切り替え)でよいか。別のタブ(「すべての団体」)にする案もあります。
2. 予定に、日程調整の候補(まだ決まっていない日)まで出すか。期限・開始日だけにする案もあります。
3. プライバシーポリシーに1文足すか(6)。
4. 問い合わせる団体の上限(10)と、1人1時間の回数の上限(120)。
