# 公開前の通しテスト

公開の前に、次の3つで確かめます。1と2は自動、3は人が本番の Google のログインで確かめます。

| | 何を確かめるか | どう動かすか |
|---|---|---|
| 1. API の通しテスト | レジストリと2つの団体の GAS を、空のスプレッドシートから本番と同じ手順で立ち上げ、ログイン・セッション・権限の確かめは本物のコードのまま操作する | `pnpm test`(`lib/ohsumi/e2e-release.test.ts`。CI でも毎回動く) |
| 2. 画面の通しテスト | ビルドした画面をヘッドレスの Chrome で開き、画面からの通信を 1 と同じ GAS につなぐ | `pnpm test:e2e`(`e2e/browser.e2e.ts`。前のビルドを使う時は `E2E_SKIP_BUILD=1`。CI では check:layout の後に動く) |
| 3. 本番の Google での確かめ | Google の本物の ID トークン・本物のスプレッドシート・メール | 下の「3. 手で確かめること」 |

1・2 では、Google のサービスだけを偽物にしています(ID トークンの確かめ `tokeninfo`・メール・Drive・カレンダー・トリガー)。
スプレッドシート・スクリプトプロパティ・キャッシュはメモリの上で動かします(`lib/ohsumi/e2e/world.ts`)。

## 1・2 で確かめること

| 項目 | API(1) | 画面(2) |
|---|---|---|
| ログイン | 登録されていないアカウントは入れない・ほかの団体のための ID トークン(nonce)・壊れたトークン・使い回しは断る | 招待リンク(`?org=`)で開くとその団体のログイン画面・登録されていないアカウントは入れない・代表は入れて ADMIN が出る |
| 新しい団体の立ち上げ | 登録コードの発行 → 団体の GAS の登録 → 初期設定コードで最初の代表(コードは1回だけ) | (1 で立ち上げた団体を使う) |
| メンバーの登録からログイン | 代表がメンバー(一般・管理者)を登録 → そのアカウントでログイン(大文字・空白の違いも) | 一般のメンバーがログインできる |
| タスクの作成・完了・承認 | 一般が作ったタスクは承認待ち → 代表が承認 → 担当者が確認待ち → 担当者は完了にできない → 代表が完了 | ― |
| 団体間のデータの分離 | 団体A のログインは団体B の GAS で使えない・団体B に団体A のタスク・メンバー・メールアドレスが出ない・鍵と団体ID が別 | 団体A にログインしたまま団体B の招待リンクを開くと、団体B のログイン画面で、団体A のデータは出ない |
| 一般と管理者の権限 | 一般は代表・管理者の操作を使えない(`forbidden`)・管理者は管理者の操作だけ・幹部限定のタスクは一般に届かない | 一般には ADMIN が出ない |
| URL の直打ち | ― | `/about/`・`/terms/`・`/privacy/` は開ける・`/admin` などは 404 でデータが出ない・知らない団体は「見つかりません」・`/registry-admin/` はログインが要る |
| 未ログイン・ログアウトの後 | セッションが無い・壊れた・書き換えた時は読み書きできない・ログアウト(全端末)の後は同じセッションを使えない・休止したメンバーはログインできない | ログアウトするとログイン画面に戻り、読み込み直してもログインしたままにならない |

画面は、アプリの中の画面(ワークスペース・管理など)を URL ではなく画面の中で切り替えます。そのため「管理の画面の URL を直打ちする」経路はありません。
管理の操作は、URL ではなく GAS が役職で断ること(1 の「権限」)で守っています。

## 3. 手で確かめること(公開の前日・テスト環境の団体で)

1. 新しいブラウザ(シークレットウィンドウ)で招待リンクを開き、本物の Google のアカウントでログインできる。
2. 初期設定コードで最初の代表になり、メンバーを登録して招待のメールが届く。そのメンバーが別の端末でログインできる。
3. タスクを作り、承認・確認待ち・完了まで進める。担当者・確認する人にメールが届く。
4. ログアウトの後、ブラウザの戻るボタンでデータが見えない。
5. 「全端末でログアウト」の後、別の端末で操作すると、ログインし直しになる。
6. デモの団体(レジストリでデモの印を付けた団体)で、上の 1〜5 を確かめる。
