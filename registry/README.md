# Ohsumi レジストリ

FSIF が1つだけ運用する、団体の一覧と状態を管理する仕組みです。設計は「Ohsumi レジストリ 設計案」を参照してください。

- **持つもの:** 団体ID・団体の GAS の URL・契約状態・チャンネル・担当者の連絡先・団体の属性・利用状況の集計値
- **持たないもの:** 団体のデータ(メンバー・タスクなど)、メンバーのメールアドレス
- **入口の向き:** レジストリから団体の GAS へ指示を送る入口は作りません。団体の GAS とフロントが問い合わせに来ます

| ファイル | 置き場所 |
|---|---|
| `registry/Code.gs` | レジストリ専用の Google アカウントのスプレッドシートの Apps Script |
| `registry/monitor/Monitor.gs` | 監視用の別の Google アカウントの Apps Script(スプレッドシートは不要) |
| `app/registry-admin/`・`components/registry/`・`lib/registry/` | 管理画面(`<サイトの URL>/registry-admin/`。Ohsumi の画面からはリンクせず、検索エンジンにも載せない) |

**サイトの URL:** 以下では Ohsumi のサイトの URL を `<サイトの URL>` と書きます。
今は `https://ohsumittm.github.io`、独自ドメインに移った後は `https://ohsumi.fsif.jp` です。
コード・CSP にはサイトの URL を書いていません(CSP は `'self'`、ログインの確認は OAuth クライアント ID で行うため)。
ドメインを移る時に変えるのは、Google Auth Platform の「承認済みの JavaScript 生成元」(1.5 の (1))だけです。

テストは `lib/ohsumi/registry.test.ts`・`lib/ohsumi/registry-admin.test.ts`・`lib/ohsumi/registry-register.test.ts`・
`lib/ohsumi/registry-monitor.test.ts`・`lib/ohsumi/registry-suspension.test.ts`(停止の予定・checkIn・予告)・
`lib/ohsumi/gas-org-register.test.ts`(団体の GAS の登録と初期設定コード)・`lib/ohsumi/gas-contract.test.ts`(団体の GAS の停止の扱い)・
`lib/ohsumi/contract.test.ts`(画面の停止の知らせ)・
`lib/registry/admin-api.test.ts` です(`pnpm test` で実行)。管理画面のスマホの幅(375px)の確認は `pnpm check:layout` に入っています。

## 1. レジストリの設定

### 1.1. アカウント

1. **レジストリ専用の Google アカウント(個人向け Gmail)を新しく作ります。** ほかの用途には使いません
2. 2段階認証を有効にし、できればセキュリティキーを登録します。ログインできる人は2人までにします
3. このアカウントでは、ほかのファイルの共有を受けたり、ほかのサービスに連携したりしません

### 1.2. スプレッドシートと Apps Script

1. レジストリのアカウントで、新しいスプレッドシートを作ります(名前の例: `Ohsumi レジストリ`)。**誰とも共有しません**
2. 「拡張機能」→「Apps Script」を開き、`registry/Code.gs` の中身を貼り付けて保存します
3. エディタで `setupRegistry` を実行します(初回は権限の確認が出ます)。次のものを作ります
   - シート: Orgs・Contacts・Attributes・Usage・RegistrationCodes・Secrets・AuditLog
   - Secrets と AuditLog の保護(GAS だけが書き込むシート)
   - スクリプトプロパティ `HEALTH_KEY`(監視の GAS が使う鍵。**実行ログに表示されるので、1.4 で監視の GAS に入れます**)
   - スクリプトプロパティ `ADMIN_SESSION_KEY`・`ADMIN_SESSION_KID`(管理画面のセッションの署名の鍵。Ohsumi 本体の鍵とは別。値は表示しません)
   - バックアップのフォルダ(マイドライブの「Ohsumi レジストリのバックアップ」)
   - 毎日のバックアップのトリガー(午前3時台)
4. 「デプロイ」→「新しいデプロイ」→「ウェブアプリ」で、次の設定でデプロイします
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
5. 表示されたウェブアプリの URL を控えます(監視の GAS と、サイトの GitHub Secrets の `REGISTRY_URL` で使います)。
   **デプロイの画面に出る URL(`https://script.google.com/macros/s/<ID>/exec`)をそのまま使います。**
   複数の Google アカウントにログインしたブラウザのアドレスバーからコピーした URL(`/u/1/` を含むもの)や、
   `/dev` の URL は使えません(Google の転送で POST の本文が失われ、レジストリに GET で届きます。
   その時レジストリは `getReceived: true` を返し、監視は「GET で届きました」と知らせます)

`setupRegistry` は何度実行しても同じ結果になります(鍵は変えず、トリガーは1つだけ、足りない列だけを足します)。
コードを更新した時は、貼り付け直して「デプロイを管理」→ 同じデプロイの版を新しくします(URL を変えないため)。

### 1.3. 管理者(スクリプトプロパティ `ADMIN_EMAILS`)

管理画面に入れるのは、スクリプトプロパティ `ADMIN_EMAILS` に書いたメールアドレスの人だけです(最初は2人)。
「プロジェクトの設定」→「スクリプト プロパティ」で、管理者の Google アカウントのメールアドレスをカンマ区切りで入れます
(例: `admin1@example.com,admin2@example.com`。大文字・小文字は区別しません)。

- 管理者の Google アカウントは、2段階認証を必ず有効にしてください(ログインの情報からは確かめられないため、運用の決まりにします)
- **追加・削除は、このプロパティを書き換えるだけです。** 削除した人は、ログイン中でも次の操作から断られます
- 許可リストに無い人がログインしようとした時は、操作の記録に「ログインを断った」と残ります
- 全員をすぐにログアウトさせたい時は、エディタで `rotateAdminSessionKey` を実行します(セッションの鍵を作り直します)
- 権限の区別(閲覧だけ / 操作)は、第1段階では設けません。許可リストの全員が操作できます
- R1-a の README にあった Admins シートは使いません(`setupRegistry` も作りません。既に作ってある場合は、消してかまいません)

### 1.4. 監視の GAS

1. **レジストリとは別の** Google アカウント(FSIF の運用用)で、新しい Apps Script のプロジェクトを作ります
   (script.google.com →「新しいプロジェクト」)
2. `registry/monitor/Monitor.gs` の中身を貼り付けて保存します
3. 「プロジェクトの設定」→「スクリプト プロパティ」に次の4つを入れます(値はコードに書きません)

   | プロパティ | 値 |
   |---|---|
   | `REGISTRY_URL` | 1.2 で控えたレジストリのウェブアプリの URL |
   | `HEALTH_KEY` | 1.2 の `setupRegistry` の実行ログに出た鍵 |
   | `ALERT_EMAILS` | 知らせる先のメールアドレス(カンマ区切り) |
   | `DISCORD_WEBHOOK_URL` | 知らせる先の Discord の Webhook の URL |

4. エディタで `setupMonitor` を実行します。15分ごとの確認と、毎朝8時台の「監視は動いています」のトリガーを作り、
   メールと Discord に試しの通知を送ります。**通知が届くことを確かめてください**
5. 止まった時の通知も確かめます。**レジストリのデプロイはアーカイブしないでください**(アーカイブしたデプロイは元に戻せず、
   新しくデプロイし直すと URL が変わります)。代わりに、**監視の GAS のスクリプトプロパティを一時的に変えて**確かめます。
   15分ごとのトリガーを待つ代わりに、エディタで `checkRegistry` を2回実行すると、すぐ確かめられます(1回の失敗では知らせません)

   **(a) 鍵が違う時**(レジストリの GAS が `r1b-2` 以降、監視の GAS もこの版の `Monitor.gs` の時。古い版のレジストリは鍵の違いを
   知らせないため、「🟠 バックアップがまだ一度も作られていません」が届きます。先にレジストリの GAS を更新し、「デプロイを管理」→
   鉛筆のアイコン →「バージョン: 新バージョン」で、**同じ URL のまま**新しい版にしてください)
   1. 監視の GAS の `HEALTH_KEY` の値を控えてから、最後の1文字だけ別の文字に変えて保存します
   2. `checkRegistry` を2回実行し、メールと Discord に「🔴 レジストリの状態を確かめられません(… 鍵(HEALTH_KEY)が違います …)」が届くことを確かめます
   3. `HEALTH_KEY` を控えた値に戻し、`checkRegistry` を1回実行して「🟢 レジストリの状態を確かめられるようになりました」が届くことを確かめます

   **(b) 応答が無い時**
   1. 監視の GAS の `REGISTRY_URL` の値を控えてから、`/macros/s/` の後ろの ID の最後の1文字だけ別の文字に変えて保存します
      (存在しないウェブアプリになり、Google が 404 を返します。`/exec` などの形は変えないでください)
   2. `checkRegistry` を2回実行し、「🔴 レジストリが応答しません」が届くことを確かめます
   3. `REGISTRY_URL` を控えた値に戻し、`checkRegistry` を1回実行して「🟢 レジストリが復旧しました」が届くことを確かめます

   **終わったら、`HEALTH_KEY` と `REGISTRY_URL` が元の値に戻っていることを必ず確かめてください**(戻し忘れると、本当に止まった時に気付けません。
   毎朝の「監視は動いています」の通知にも、レジストリが「停止中」と出ます)。試している間、レジストリの GAS とデプロイには何も触れません

### 監視が知らせること

| 通知 | 条件 |
|---|---|
| 🔴 応答しません | 2回続けて(15〜30分)応答がない・応答がおかしい |
| 🟢 復旧しました | 止まった後に応答が戻った(止まっていた時間を付ける) |
| 🔴 状態を確かめられません | 2回続けて、鍵(`HEALTH_KEY`)が違うとレジストリが答えた(レジストリの `HEALTH_KEY` を変えた後、監視側の更新を忘れた時など)。バックアップなどの監視も効いていません |
| 🟢 状態を確かめられるようになりました | 鍵が合うようになった |
| 🟠 バックアップ | 最後のバックアップから26時間を超えた(まだ一度も無い時も) |
| 🟠 記録の無い変更 | Orgs の接続先・状態・チャンネル・停止の予定が、操作の記録なしに変わっている(スプレッドシートの直接の編集) |
| 🟠 断ったリクエスト | 回数の上限で断ったリクエストが、1時間に1000回を超えた(攻撃の疑い) |
| ✅ 解消しました | 🟠 の問題が無くなった |
| 監視は動いています | 毎朝1回、Discord にだけ送る。**届かない日は、監視の GAS が止まっています**。団体の GAS の更新が要る団体の数・24時間以上確認が無い団体の数・毎日の処理が26時間以上成功していない団体の数も書きます(1.10) |

それぞれ、起きた時に1回、解消した時に1回だけ知らせます。

### 1.5. 管理画面(`/registry-admin/`)

管理画面は、Ohsumi のサイト(`<サイトの URL>/registry-admin/`)の中の、どこからもリンクしていないページです。
検索エンジンには載せません(noindex)。ログインと判定はすべてレジストリの GAS が行います。

#### (1) ログイン用の OAuth クライアントを作る(Google Auth Platform)

Ohsumi 本体とは別の、レジストリ用の OAuth クライアントを作ります。**すべてレジストリのアカウントで行います。**

1. レジストリのアカウントで https://console.cloud.google.com/ を開き、新しいプロジェクトを作ります(名前の例: `ohsumi-registry`)
2. 左のメニューの「Google Auth Platform」を開き、「開始」を押して次のとおり入力します
   - アプリ名: `Ohsumi レジストリ管理`
   - ユーザー サポートメール: レジストリのアカウントのメールアドレス
   - 対象: **外部**
   - 連絡先情報: レジストリのアカウントのメールアドレス
3. 「対象」で、公開ステータスを **テスト** のままにし、「テストユーザー」に **管理者2人の Google アカウント**を追加します
   (テスト中のアプリは、テストユーザーだけがログインできます。`ADMIN_EMAILS` に加えた、もう1つの入口の制限になります)
4. 「データアクセス」は何も追加しません(使うのは、ログインに必要な基本の情報〈メールアドレス〉だけです)
5. 「クライアント」→「クライアントを作成」で、次のとおり作ります
   - アプリケーションの種類: **ウェブ アプリケーション**
   - 名前: `registry-admin`
   - 承認済みの JavaScript 生成元: `https://ohsumittm.github.io`
     - **独自ドメイン(`https://ohsumi.fsif.jp`)に移る時に、ここへ `https://ohsumi.fsif.jp` を追加します。**
       移る前に追加しておけば、切り替えた直後からログインできます。古い `https://ohsumittm.github.io` は、新しいドメインでログインできることを確かめてから消します
       (生成元は末尾の `/` やパスを付けずに入れます。反映に数分かかることがあります)
   - 承認済みのリダイレクト URI: 入れません
6. 表示された **クライアント ID**(`….apps.googleusercontent.com`)を控えます(秘密ではありませんが、ここ以外には使いません)

#### (2) レジストリの GAS に設定する

1. レジストリの Apps Script を、この版の `registry/Code.gs` に貼り替えて保存します
2. 「プロジェクトの設定」→「スクリプト プロパティ」に次の2つを入れます

   | プロパティ | 値 |
   |---|---|
   | `OAUTH_CLIENT_ID` | (1) で控えたクライアント ID |
   | `ADMIN_EMAILS` | 管理者のメールアドレス(カンマ区切り。1.3) |

3. エディタで `setupRegistry` を実行します。管理画面のセッションの鍵を作ります。
   初回は権限の確認が出ます(Google のログインの確認に「外部サービスへの接続」を使うため)。レジストリのアカウントで許可します
4. 「デプロイ」→「デプロイを管理」→ 鉛筆のアイコン →「バージョン: 新バージョン」→「デプロイ」で、**同じ URL のまま**新しい版にします

#### (3) 画面に設定する(GitHub Secrets)

OhsumiTTM/OhsumiTTM.github.io の「Settings」→「Secrets and variables」→「Actions」に、次の2つを入れます。

| Secret | 値 |
|---|---|
| `REGISTRY_URL` | レジストリのウェブアプリの URL(1.2 で控えたもの。`https://script.google.com/macros/s/<ID>/exec`) |
| `REGISTRY_OAUTH_CLIENT_ID` | (1) で控えたクライアント ID |

「Actions」→「Deploy to GitHub Pages」→「Run workflow」で、サイトを作り直します。
`REGISTRY_URL` の形が違う(`/u/1/` を含む・`/dev`)と、ビルドが止まります。

#### (4) 確かめる

1. `<サイトの URL>/registry-admin/` を開き、管理者のアカウントで「Google でログイン」します。団体の一覧が出ることを確かめます
2. 許可リストに無いアカウントでログインし、「管理者として登録されていません」と出ること、「操作の記録」に「ログインを断った」が残ることを確かめます
   (Google Auth Platform のテストユーザーに入っていないアカウントは、Google の画面で止まります。それも正しい動きです)
3. 「登録コード」で試しのコードを発行し、コードが1回だけ表示されること、一覧に「未使用」で出ることを確かめます
4. そのコードを「取り消す」で取り消し、一覧で「取り消し済み」になること、「操作の記録」に発行と取り消しが残ることを確かめます
5. スプレッドシートの RegistrationCodes シートを見て、コードそのものが無く、`sha256:` で始まる値だけがあることを確かめます

#### 管理画面の決まり

| 項目 | 決まり |
|---|---|
| ログイン | Google の ID トークンを、レジストリの GAS が tokeninfo で確かめる(発行元のクライアント・nonce・メールの確認済み)。同じ ID トークンは1回だけ |
| セッション | 30分で切れ、延長しない。このタブにだけ保存する(タブを閉じると消える)。署名の鍵は Ohsumi 本体と別 |
| 登録コードの発行 | 5分以内に Google でログインしたセッションだけ(古ければ、入力を残したままログインし直す) |
| 登録コード | 16文字(読み間違えない31種類の文字。約79ビット)、4文字ずつ区切って表示。有効期限14日、1回だけ使える。**発行した画面で1回だけ表示し、レジストリには SHA-256 だけを保存する** |
| 取り消し | 未使用のコードだけ。理由を付けられる。元に戻せない |
| 一覧 | 団体・登録コード・操作の記録(新しい順に200件)を1回の通信で受け取る |
| 停止の予定 | 5分以内に Google でログインしたセッションだけ(古ければ、入力を残したままログインし直す)。今から14日より後だけ。ただし提供停止(①)は、確認の画面を挟んで当日に停止できる(緊急)。取り消し・解除は、いつでもできる(1.9) |
| プラン | 団体ごとに、Cosmo Base・Ohsumi・有償を記録する(「プランを変える…」)。有償の団体には、機能停止(②)を入れられない(1.9) |
| 操作の記録 | ログイン・ログインを断った・発行・取り消し・鍵の作り直し・停止の予定・取り消し・解除・予告の送信を、誰が・いつ・何をしたか(と理由)で AuditLog に残す。コードもハッシュも記録には入れない |
| 送り直し | 一覧の読み込みは、応答が無ければ2回まで送り直す。発行・取り消しは送り直さない(二重に発行しないため。失敗した時は一覧で確かめる) |

## 1.6. データの形(R1-c〜R1-e で使う列も用意済み)

### Orgs(団体)

| 列 | 内容 | 使う段階 |
|---|---|---|
| `org_id` | 団体ID(団体の GAS の ORG_ID。約120ビットの乱数) | R1-c |
| `gas_url` | 接続先(団体の GAS のウェブアプリの URL) | R1-c・R1-d |
| `status` | `active` / `suspended`(実際に止めているか。停止の解除で `active` に戻す) | R1-e |
| `channel` | 配信のチャンネル(第1段階は `standard`) | R1-c |
| `display_name` | 団体名(登録コードの団体名から) | R1-c |
| `created_at` | 登録日 | R1-c |
| `suspend_at`・`suspend_reason`・`suspend_scheduled_by` | 停止の予定日時・理由・予定を入れた管理者 | R1-e |
| `suspend_notices_json` | 停止の予告を送った記録(14日前・7日前・1日前) | R1-e |
| `suspend_kind` | 停止の種類: `suspend`(① 提供停止)/ `restrict`(② 機能停止)。空は `suspend` とみなす | R1-e |
| `plan` | プラン: `cosmo_base`(Cosmo Baseプラン)/ `ohsumi`(Ohsumiプラン)/ `paid`(有償プラン)。空は未設定。管理画面で変え、操作の記録に残す | R1-f |
| `last_check_at`・`gas_version` | 団体の GAS が最後に契約状態を確認に来た時刻・その版 | R1-e |
| `contract_status`・`contract_until`・`contract_note` | 契約の状態(`active` 契約中 / `ending` 終了予定 / `ended` 終了)・終了日・メモ | R1-e |
| `updated_at` | 最後に変えた時刻 | R1-c〜 |

管理画面の一覧の「状態」は、次のように出します(`orgDisplayState_`)。

- **提供停止中:** `status` が `suspended`、または種類が `suspend` で停止の予定日時を過ぎた
- **機能停止中(読み取り専用):** 種類が `restrict` で、停止の予定日時を過ぎた
- **停止予定:** 停止の予定日時が入っていて、まだその前(種類も印で出します)
- **有効:** それ以外
- 別の印として、**「確認が7日以上ありません」**(最後の確認から7日を超えた)・**「まだ確認がありません」**(一度も確認に来ていない)を出します

### RegistrationCodes(登録コード)

`code_id`(一覧・取り消しで使う番号)・`code_hash`(`sha256:` + 16進数)・`kind`(`new`。R1-c の再登録コードは `reissue`)・
`target_org_id`・`org_name`・`contact_name`・`contact_email`・`note`・`expires_at`・`issued_by`・`issued_at`・
`used_at`・`used_org_id`・`revoked_at`・`revoked_by`。

コードは、団体の登録(`registerOrg`。R1-c)で使います。
無いコード・使用済み・期限切れ・取り消し済みは、区別せず同じエラーを返します(当てずっぽうの手がかりにしないため)。

### Usage(定量データ。PR N)

団体の GAS が週1回送る、個人を特定しない集計値(`reportMetrics`)。1行が1団体・1期間です。

| 列 | 内容 |
|---|---|
| `org_id` | 団体ID |
| `date` | 期間(その週の月曜日 `YYYY-MM-DD`) |
| `metrics_json` | 集計値(各項目の定義は `gas/README.md` の「4.18」)。知らない項目・0 未満・数でない値は捨てる |
| `metrics_version` | 定義の版 |
| `received_at` | 最後に受け取った日時(同じ期間の送り直しは上書きする) |

署名は `base64url(HMAC-SHA256(共有鍵, 'metrics.' + orgId + '.' + ts + '.' + period + '.' + JSON.stringify(metrics)))`。時刻は前後5分までです。
checkIn の返事に、団体のプラン(`plan`)を入れます(団体の GAS が送るかを決めるため)。

## 1.7. 接続先の解決(R1-d)

計測では、GAS のウェブアプリは何もしない ping でも1回あたり約1.3〜2.5秒、たまに10秒以上かかります。
利用者のログインのたびにレジストリへ問い合わせると、その分ログインが遅くなるので、次の形にしています。

- **招待リンク:** `<サイトの URL>/?org=<団体ID>`。メンバーは、初めての端末でこのリンクから開きます。開いた後、アドレスバーから `?org=` を消します。
  - 招待リンクは、代表が管理画面の「Members」で確かめられます(コピーのボタンがあります)。
  - レジストリの管理画面の「団体」にも出ます。登録のダイアログには、団体ID と作り方を出します。
- **API:** `resolveOrg`(認証なし)。
  - 要求は `{ action: 'resolveOrg', orgId }` です。
  - 返事は `{ ok: true, result: { orgId, gasUrl, status: 'active' | 'restricted' | 'suspended', channel, checkedAt, maxAgeSec } }` です。
  - 答えるのは、団体ID が完全に一致した時だけです。一覧・検索はありません。
  - 無い ID・形の違う ID には、どちらも同じ `{ ok: false, notFound: true }` を返します。
  - 提供停止中の団体には、`status: 'suspended'` だけを返します(接続先は返しません)。
  - 機能停止中の団体には、接続先と `status: 'restricted'` を返します(読み取り専用で使えるので、画面はふつうにつなぎます)。
  - 団体名・担当者・属性・利用状況は返しません。
  - 回数は1分に120回までです(レジストリ全体)。
- **画面は、接続先を一度わかったら保存し、毎回は問い合わせません。**
  - 保存する場所は、この端末の「所属する団体の一覧」(localStorage の `ohsumi-orgs`)です。団体ID・接続先・団体名・確かめた時刻を持ちます。
  - 保存した接続先があれば、それを使ってすぐにログインを始めます(ログインの後の再読み込みも同じです)。
- **保存した接続先が `maxAgeSec`(24時間)より古い時**
  - 保存した接続先で始めるのと同時に、裏で `resolveOrg` を送り、保存を新しくします。
  - 答えが保存と違った時だけ、その団体のログインを終えます。「接続先が変わりました」「利用を停止しています」「見つかりません」のどれかを出して、ログイン画面に戻します。
- **初めての端末(招待リンクの団体が一覧に無い時)**
  - レジストリの答えを待ちます。
  - その後、答えの GAS に `getLoginConfig` を送り、団体ID が同じことを確かめてから、「Google でログイン」のボタンを出します。
  - 設計案では「待つ間にボタンを出す」としていました。しかし、接続先が決まる前に押されると、Google の ID トークンを別の団体の GAS に送ってしまいます。そのため、答えを待ってからボタンを出す形にしました。
- **レジストリの側:**
  - `resolveOrg` の答えを、CacheService に団体ごとに10分覚えます(無い団体は1分)。覚えている間は、シートを読みません。
  - 登録・再登録(接続先の変更)の時は、その団体の覚えた答えを消します。R1-e の停止でも消します。
- **レジストリが止まっている時**
  - 保存した接続先があれば、使い続けます。
  - 初めての端末では「接続先を確認できません」と、「もう一度試す」のボタンを出します(GAS の URL を手で入れる欄はありません)。
- **招待リンクなしで開いた時:** 今の団体(最後に使った団体)があれば、その団体を使います。
  - 今の団体が無い端末には、「団体から届いた招待リンクを開いてください」と出します。この端末の団体の一覧に団体があれば、その一覧から選べます。
  - ビルド時に決まる「既定の団体」(以前の GitHub Secrets の `CSV_GAS`)はありません(R1-f 後半で消しました)。
    以前の既定の団体の保存(一覧の `source: 'default'` の項目)と、R1-d より前の保存(`ohsumi-login-config`)は読みません。
- **1つの端末で複数の団体**
  - ログイン画面で、一覧から団体を選べます(一覧に2つ以上ある時)。
  - ログインの情報は、団体ごとに分けて保存します。ある団体の GAS に、別の団体のトークンを送ることはありません。
  - 団体を切り替えると、団体ごとの表示の保存(団体名・ロゴ・テーマ色など)を消して、ページを読み込み直します。

## 1.8. コードを貼り替える時

- **レジストリ(`registry/Code.gs`):** 貼り替えて保存し、エディタで `setupRegistry` を実行してから、「デプロイを管理」で
  今のウェブアプリを「新バージョン」にします(URL は変わりません)。
  - R1-e から、停止の予告のメールを送ります(MailApp)。貼り替えた後の `setupRegistry` の実行で、メールの送信の許可を求められたら許可してください。
  - PR E から、`setupRegistry` が `GasVersions` シート(版の印)を作ります。
- **監視(`registry/monitor/Monitor.gs`):** 貼り替えて保存し、エディタで `setupMonitor` を実行します(知らせる先に試しの通知が届きます)。
- どちらの `setup…` も、最初に、今のコードに無い関数を指すトリガー(以前の版の名前のまま残ったもの)を消します。
- エディタの関数の一覧に出るのは、エディタから実行する関数と、入口・トリガーから呼ばれる関数だけです。
  中で使うだけの関数は、名前の最後に `_` を付けています。一覧と説明は、それぞれのファイルの先頭のコメントにあります。

## 1.10. GAS の版(PR E)

- **版の形:** 団体の GAS(`gas/Code.gs` の `OHSUMI_GAS_VERSION`)・レジストリ(`REGISTRY_VERSION`)・監視(`MONITOR_VERSION`)の版は、
  日付の形「YYYY.MM.DD-N」です(日本の日付。同じ日の2回目は `-2`)。
  - ファイルを変えたら `pnpm gas:version` を実行します。中身が変わったファイルだけ版を上げ、`gas/versions.json` に中身のハッシュと版を書きます。
  - 版を上げ忘れると、テスト(`lib/ohsumi/gas-version.test.ts`)が失敗します。
  - 団体の GAS の新しい版を出したら、`registry/Code.gs` の `KNOWN_GAS_VERSIONS` にも足します(足し忘れもテストが止めます)。
  - **反映の順番は、レジストリ → 団体の GAS です。** 先にレジストリを貼り替えて新しい版を一覧に入れてから、団体の GAS を更新します。
    逆にすると、一覧に無い新しい版の団体は「最新」と出ますが、ほかの団体の「古い」「更新が要る」の判定が、一覧が新しくなるまで正しく出ません。
- **版の一覧と印:** 版の一覧は `KNOWN_GAS_VERSIONS` に、管理画面で付けた印(`GasVersions` シート)を重ねたものです。
  - 印は2つあります。「安全の修正」と「これより古ければ更新が要る」です。管理画面の「団体」の上の「団体の GAS の版の一覧」で付け直せます(操作の記録に残ります)。
  - 最初の「安全の修正」の版は `2026.10.01-1` です(通知・タスクの書き換えを GAS が守る修正〈PR A〉を含む最初の版)。
    それより前の版(`r1e-2` など、日付の形でない版)は、どの日付の版よりも古いとみなします。
- **判定(団体ごと):** 管理画面の団体の一覧に、版と判定を出します。
  - 最新
  - 古い(一覧の一番新しい版より古い)
  - 更新が要る(印の付いた一番新しい版より古い)
  - 24時間以上確認が無い(最後の checkIn から24時間を超えた。版の判定より優先して出します)
  - 「GAS の更新が要る団体だけ」で絞り込めます。24時間以上確認が無くても、最後に伝えられた版で更新が要る団体は入ります。
- **更新のお願い:** 判定が「最新」でない団体には「担当者に更新のお願いを送る…」のボタンを出します。
  担当者(Contacts)に、今の版・最新の版・更新の手順をメールで送ります。同じ団体には24時間に1回までで、操作の記録に残ります。
- **団体の GAS への知らせ:** checkIn の返事に `gasUpdate: { required, outdated, latest, minimum, security }` を入れます。
  - 団体の GAS は、代表・全権管理者の管理画面の上部に「この団体の GAS の更新が要ります」を出します。
  - 代表には、最新の版ごとに1回だけメールで知らせます(1時間ごとの確認から)。
- **監視の毎日のまとめ:** 毎朝の「監視は動いています」に、次の数を書きます。どちらも利用中(status が active)の団体だけを数えます。
  - 更新が要る団体の数
  - 24時間以上確認が無い団体の数
  - 監視は health に `summary: true` を付けて聞きます(15分ごとの確認では Orgs を読みません)。
- **スクリプトプロパティのキャッシュ:** レジストリは、通信のたびにスクリプトプロパティを読み直さず、5分間 CacheService に置きます(この GAS だけが読めます)。
  - GAS が書き換えた時(指紋・鍵・バックアップの時刻など)は、すぐに捨てます。
  - **エディタでスクリプトプロパティを手で変えた時(`ADMIN_EMAILS`・`SITE_ORIGINS` など)は、反映まで最大5分かかります。**
  - 版の一覧も、同じく5分キャッシュに置きます(印を付け直した時は、すぐに捨てます)。

## 1.9. 提供停止・機能停止(R1-e)

停止には2つの種類があります。どちらも、管理画面の「団体」で **「停止の予定を入れる…」** から、種類・日時・理由を入れます。

| | ① 提供停止(`suspend`) | ② 機能停止(`restrict`) |
|---|---|---|
| 使う時 | 契約の終了・規約違反など | アンケートの未回答など |
| 団体の画面 | 全員が使えなくなります。ログイン画面に「この団体は、Ohsumi の利用を停止しています」を出します | 全員が読み取り専用になります(閲覧と書き出しはでき、作成・編集はできません)。画面の上部に「アンケートへの回答をお願いします。回答が確認でき次第、再開します」を出します(画面の扱いは下の「読み取り専用の画面」) |
| 団体の GAS | ログインの設定(`getLoginConfig`)以外のすべての操作を断ります。通知・毎朝の処理も止めます | ログイン・読み取りだけを受け付けます。通知・毎朝の処理は止めません |
| 団体のデータ | 団体のスプレッドシートにそのまま残ります(消しません) | 同じ |
| 元に戻す | 管理画面の「停止を解除する…」 | 同じ。使われていれば1分以内に元に戻ります |

- **予告(どちらの種類も同じ):** 停止の14日前・7日前・1日前に、メールで知らせます。
  - レジストリは、担当者(Contacts のメールアドレス)に、毎日の処理(`dailyRegistryBackup`)で送ります。送った予告は `suspend_notices_json` に残します。
  - 団体の GAS は、代表(最上位の役職のメンバー)に、1時間ごとの確認(`checkContractStatus`)で送ります。
  - 団体の画面にも、14日前から上部に予告を出します(停止の理由は画面には出さず、メールにだけ書きます)。
- **読み取り専用の画面(② 機能停止):**
  - 文章・数値・日付を書く欄と、ファイルの選択は、最初から使えません(書いた文章が保存できずに消えることが無いように)。
  - 閲覧のための欄は使えます: 検索、ワークスペースの期間(年/月/日)、プロジェクトの選択、表示の切り替え、並び替え(表示順)、
    表示項目、管理画面の検索・絞り込み。Excel 出力などの書き出しも使えます(`pnpm check:layout` の「機能停止中」で確かめています)。
  - 作成・編集のボタンは押せますが、画面を変える前に止まり、「読み取り専用のため、保存できません」を出します。
  - 万一 GAS に断られた時(画面が機能停止を知る前に保存した時など)も、読み込み直さずに知らせ、書いた文章をコピーできるように出します。
  - 機能停止中の画面は、3分ごとに読み込み直します(解除されたら、すぐ元に戻ります)。
- **予定を入れられる日時:** 今から14日より後だけです(予告を漏らさないため)。停止中の団体には、先に解除してから入れ直します。
- **当日の提供停止(緊急。① 提供停止だけ):** 停止の予定の欄で「当日に提供停止にする」を選ぶと、確認の画面を挟んで、今すぐ提供停止にします。
  - 理由は必須です。5分以内の Google でのログインも要ります。操作の記録には「当日の提供停止(緊急)」(`suspendNow`)として残ります。
  - 14日前の予告は送れないので、担当者(Contacts のメールアドレス)には、その場でメールで知らせます。
  - 団体の GAS が次に状態を確かめた時に効きます(書き込みがあれば10分以内、遅くとも1時間以内。使っている端末の画面は、次の操作で「利用を停止しています」に変わります)。
  - 機能停止(②)は、当日にはできません(これまでどおり14日より後だけ)。
- **プラン:** 団体ごとに記録します(`plan`。管理画面の「プランを変える…」)。
  - 有償プラン(`paid`)の団体には、機能停止(②)を入れられません(アンケートに回答が無い時は、サポートの停止のみのため)。テスト環境の関数(1.9.1)でも同じです。
  - 機能停止の予定(または機能停止)が入っている団体を有償にする時は、先に取り消す・解除します。
  - プランを直接シートで書き換えると、「記録の無い変更」として監視に出ます。
- **取り消し・解除:** 予定の取り消し(`cancelSuspension`)・停止の解除(`liftSuspension`)は、いつでもできます。理由は操作の記録に残します。
  送った予告の取り消しは、担当者に別に連絡してください。
- **団体の GAS の確認(`checkIn`):**
  - 要求は `{ action: 'checkIn', orgId, ts, gasVersion, mail, sig }` です。`sig` は、共有鍵で `'checkIn.' + orgId + '.' + ts` に付けた HMAC-SHA256 の署名(base64url)です。時刻 `ts`(Unix 秒)は前後5分までです。共有鍵そのものは送りません。
  - 返事は `{ ok: true, result: { phase: 'none' | 'scheduled' | 'inEffect', kind, suspendAt, reason, checkedAt, siteOrigins } }` です。
  - `siteOrigins` は、サイトの origin の一覧です(下の「1.9.3」)。団体の GAS は、本人あての招待リンクのメールに使います。
  - 最後に確認に来た時刻と GAS の版を、Orgs の `last_check_at`・`gas_version` に書きます(10分に1回まで)。回数は1分に300回までです。
  - 要求の `jobs`(`{ dailyAt, hourlyAt }`)は、団体の GAS の毎日・毎時の処理が最後に成功した時刻です(gas/README.md の「4.15」)。
    Orgs の `daily_job_at`・`hourly_job_at` に書きます(毎日の処理が新しく成功した時は、10分を待たずに書きます。列が無い時は書きません)。
    最後に伝えられた毎日の処理の成功から26時間を過ぎた団体は、管理画面の一覧に「毎日の処理が26時間以上成功していない」と出し、監視の毎朝のまとめで数えます
  - 要求の `mail`(`{ remaining, skipped, date, lastReachedDate }`)は、団体の GAS のメールの1日の上限の状態です
    (残りの数・その日に上限で送れなかった数・その日・最後に上限に達した日。gas/README.md の「4.12」)。
    Orgs の `mail_remaining`・`mail_skipped`・`mail_date`・`mail_limit_date` に、上と同じ時に書きます(送れなかった数が変わった時は、10分を待たずに書きます)。
    指紋(記録の無い変更の検出)には入れません。列が無い時(`setupRegistry` を実行し直していない時)は書きません。
    管理画面の団体の一覧に「メールの上限に達した」(最後に伝えられた日に上限に達した)・「メールの残り n」(残りが20件以下)を出し、一覧の上にその団体の数を出します
  - 団体の GAS は、1時間ごとに確かめます。リクエストの時にも確かめ直します。
    - 停止中(予定の日時を過ぎた時も): 解除がすぐ効くように、どの操作でも1分に1回まで。
    - 停止の予定がある時: 書き込み(読み取りの一覧に無い操作)の前に、1分に1回まで。
    - 停止の予定が無い時: 書き込みの前に、10分に1回まで(読み取りでは問い合わせないので、読み込みは遅くなりません)。
  - 機能停止中の団体の GAS は、読み取りの一覧(`READ_ONLY_ACTIONS`: 読み取り・ログイン・ログインの記録・ログインの無効化)に
    無い操作を、すべて断ります。まとめて送る書き込み(batch)も断ります。新しく足した操作も、一覧に足さない限り断ります。
    初期設定コードで代表を入れるログインも断ります(メンバーを足すため)。
  - **画面の停止の表示は、団体の GAS が応答に付けた状態だけで決まります。** GAS が今その状態で動いている時だけ、画面も読み取り専用に
    なります(画面は、予定の日時を過ぎたことを自分では判断しません)。予告の表示には「今は、これまでどおり使えます」と書きます。
  - **レジストリに確かめられない時は、団体の GAS は最後に確かめた状態のまま使い続けます。** ただし、最後に届いた停止の予定の日時は守ります。
- **団体の GAS の版:** R1-e より前の団体の GAS は、確認に来ません(一覧に「まだ確認がありません」が出ます)。停止の予定を入れる前に、団体の GAS を
  R1-e の版に貼り替え、`setupOhsumi` を実行してもらってください(gas/README.md の「4.2.1」)。確認に来ない団体では、画面での停止はレジストリの
  接続先の解決(`resolveOrg`)だけで行われ、保存した接続先を使う端末では最大24時間遅れます。

### 1.9.3. サイトの origin(スクリプトプロパティ `SITE_ORIGINS`)

団体の GAS は、サイトの URL を次の場面で使います(gas/README.md の「4.9」「4.11」)。
- 画面の「ほかの端末で開く」→「自分のメールに送る」: 本人の登録済みのアドレスに招待リンク(`<サイトの origin>/?org=<団体ID>`)を送る
- 新しいメンバーへの招待メール
- 通知メール・Discord/Slack・カレンダーの予定に付けるリンク(正式なサイト = 一覧の最初)
- レジストリに登録した時のメッセージの招待リンク
団体の GAS はサイトの URL を知らないので、レジストリが `checkIn` の返事で配ります
(サイトの URL はコードに書きません。`lib/ohsumi/site-url.test.ts`)。

- レジストリのスクリプトプロパティ **`SITE_ORIGINS`** に、サイトの origin(`https://ホスト名`。パス・末尾の `/` は付けない)を書きます。
  **複数書けます**(カンマ・空白・改行で区切る。5つまで)。**最初のものを正式なサイト**として扱います。
  - 例(独自ドメインへ切り替える間): `https://<独自ドメイン>, https://<今のサイト>`
  - `https` でないもの・パスやユーザー名の付いたものは使いません。
- 団体の GAS は、画面が今開いている origin が一覧にあればそれを、無ければ一覧の最初を使ってリンクを作ります
  (画面が送った値を、そのままリンクにはしません)。
- 一覧が届くのは、団体の GAS が次に `checkIn` した時です(1時間ごと。書き込みの前にも、10分に1回まで)。
  切り替えの後に古いサイトを一覧から消すと、古いサイトで開いている画面からのメールには、正式なサイトのリンクが入ります。
- **レジストリに一度も確かめられていない団体・`SITE_ORIGINS` が空の時は、「自分のメールに送る」は使えません**
  (画面のボタンが押せなくなり、理由が出ます)。QR コードと共有・コピーは、そのまま使えます。

### 1.9.1. テスト環境で、14日待たずに確かめる

エディタから実行する関数で、テスト環境の団体に、停止・予定・解除をすぐ入れられます(管理画面からはできません)。

レジストリは1つだけで、本番の団体(Orbit から移行した FSIF など)も同じレジストリに登録されています。そのため:

- `test` から始まる関数は、`REGISTRY_TEST_MODE` が `true` の時だけ動きます。
- 対象にできるのは、`REGISTRY_TEST_ORG_IDS` に書いた団体(テスト環境の団体)だけです。それ以外の団体(本番の団体)を
  `TEST_ORG_ID` に入れた時は、何も変えずに止まります。**`REGISTRY_TEST_ORG_IDS` には、本番の団体ID を書かないでください。**
- **試し終わったら、`REGISTRY_TEST_MODE` を消してください**(下の「終わったら」)。

**準備(レジストリのスクリプトプロパティ)**

| プロパティ | 値 |
|---|---|
| `REGISTRY_TEST_MODE` | `true`(試す間だけ。終わったら消す) |
| `REGISTRY_TEST_ORG_IDS` | テスト環境の団体ID(複数ある時はカンマ区切り)。本番の団体ID は書かない |
| `TEST_ORG_ID` | 確かめる団体の団体ID(`REGISTRY_TEST_ORG_IDS` にあるもの。管理画面の「団体」に出ます) |
| `TEST_SUSPEND_KIND` | `restrict`(② 機能停止)か `suspend`(① 提供停止) |
| `TEST_SUSPEND_DAYS` | 予定を入れる時の、停止までの日数(例: `13.9`・`6.9`・`0.9`) |

団体の GAS はテスト環境のもの(スクリプトプロパティ `TEST_ENVIRONMENT` が `true`。gas/README.md の「11.5」)にし、`TEST_NOTIFICATION_EMAIL` に
自分のメールアドレスを入れておきます(代表への予告は、このアドレスに届きます)。

**停止の動き**

1. レジストリのエディタで `testSuspendNow` を実行します(今すぐ `TEST_SUSPEND_KIND` の停止になります)。
2. 団体のエディタで `checkContractStatus` を実行します(団体の GAS が、すぐに停止を知ります)。
   実行しなかった時も、団体の GAS は、次の書き込みの前にレジストリに確かめ直して断ります
   (前に確かめてから、予定がある時は1分、予定が無い時は10分たっていれば)。
3. Ohsumi の画面を開き直します。
   - ② 機能停止: 上部にアンケートのお願いが出て、書く欄が使えず、作成・編集が止まること。閲覧・書き出しができること。
   - ① 提供停止: ログイン画面に「この団体は、Ohsumi の利用を停止しています」が出ること。
4. レジストリのエディタで `testLiftSuspension` を実行します。画面を操作すると、1分以内に元に戻ります(② は3分ごとの読み込み直しでも戻ります)。

**予告のメール(14日前・7日前・1日前)**

1. `TEST_SUSPEND_DAYS` を `13.9` にして、レジストリのエディタで `testScheduleSuspension` を実行します。
   14日前の予告が、担当者(Contacts のメールアドレス)にすぐ届きます。
2. 団体のエディタで `checkContractStatus` を実行します。14日前の予告が、代表(テスト環境では `TEST_NOTIFICATION_EMAIL`)に届きます。
   画面の上部にも、停止の予告が出ます。
3. `TEST_SUSPEND_DAYS` を `6.9`(7日前)・`0.9`(1日前)に変えて、1〜2 を繰り返します。
   予定を入れ直すたびに予告の記録は最初からになるので、その時期の予告が1通ずつ届きます。
4. 終わったら `testLiftSuspension` を実行します。

どの操作も、操作の記録に「(テスト)」として残ります。

**終わったら**

1. `testLiftSuspension` を実行し、テスト環境の団体の停止・予定を解除します(管理画面の「団体」で「有効」に戻ったことを確かめます)。
2. レジストリのスクリプトプロパティから **`REGISTRY_TEST_MODE` を消します**(`test` から始まる関数は、どれも動かなくなります)。
   `REGISTRY_TEST_ORG_IDS`・`TEST_ORG_ID`・`TEST_SUSPEND_KIND`・`TEST_SUSPEND_DAYS` は、次に試す時のために残しても構いません。

### 1.9.2. R1-f 後半(既定の団体の片付け)を反映する時

R1-f 後半で、ビルド時に決まる「既定の団体」(GitHub Secrets の `CSV_GAS`)を消しました。反映の後は、どの端末も招待リンク
(`<サイトの URL>/?org=<団体ID>`)から開いた団体にだけつながります。今サイトを使っているのはテスト環境だけです。

**反映の前に(FSIF)**

1. テスト環境の団体が、レジストリに登録されていることを確かめます(管理画面の「団体」)。
   - 接続先が、テスト環境の GAS の今のウェブアプリの URL(`…/exec`)と同じであること。
   - 団体ID を控え、招待リンクを作っておきます(管理画面の「団体」の「招待リンク」)。
   - 登録されていなければ、先に「4.5. すでに動いている団体の登録」で登録します。
2. 端末で前もってしておくことはありません。反映の前に招待リンクを開いても、以前の既定の団体の保存のまま使うため、
   反映の後にもう一度開く必要があります。

**反映**

3. PR をマージします(`deploy.yml` は、もう `CSV_GAS` を使いません)。
4. GitHub の Settings → Secrets and variables → Actions から、`CSV_GAS` を消します
   (残っていても使いませんが、消し忘れを防ぐためです。ビルドの確認は、環境変数 `NEXT_PUBLIC_GAS_URL` が残っていればビルドを止めます)。

**反映の後に(テスト環境を使う人の各端末)**

5. サイトを開くと、「団体から届いた招待リンクを開いてください」が出ます(以前の既定の団体の保存は読まないため)。
6. 1 の招待リンクを1回開きます。団体の一覧に入り、今の団体になります。
   - 反映の前にログインしていた端末は、ログインしたままです(ログインの情報は団体ID ごとに保存していて、団体ID は変わらないため)。
   - 次からは、招待リンクなしで開いても、その団体につながります。

## 2. 安全のための決まり

- **共有鍵:** 団体の登録の時にレジストリが作り、レジストリの Secrets(保護したシート)と、団体の GAS のスクリプトプロパティ
  `REGISTRY_SHARED_KEY` にだけ置きます。操作の記録・実行ログ・管理画面には出しません(漏れた時は「4.4」)
- **登録コードの総当たり:** 登録は1分に10回まで。コードが違う・使えない登録が1時間に30回を超えたら、その1時間は
  正しいコードでも登録を受け付けません(監視の「断ったリクエスト」にも数えます)。コードは16文字(約79ビット)で、
  使えない理由は区別せず同じエラーを返します

- **スプレッドシートは誰とも共有しません。** 管理者の操作は管理画面(R1-b)から行います
- **管理者のログイン:** 許可リスト(`ADMIN_EMAILS`)の人だけ。セッションは30分、延長なし、署名の鍵は本体と別(1.5)
- **死活の確認(health):** 鍵(`HEALTH_KEY`)が無いと「動いている」ことだけを返します。鍵が違う時は、それに加えて鍵が違うこと(`keyValid: false`)だけを返します。鍵があっても、団体の情報は返しません
- **リクエストの回数の上限:** Apps Script では送り元(IP アドレス)が分からないため、レジストリ全体で数えます
  (全体で1分に600回、health は1分に60回、団体の登録は1分に10回)。上限を超えたらシートを読まずにすぐ断り、断った回数を監視に渡します
- **リクエストの大きさ:** 本文は5万文字までです
- **操作の記録(AuditLog):** 追記だけで、書き換えません(保護したシート)。R1-b 以降の操作は、すべてここに記録します
- **記録の無い直接の編集の検出:** 記録を伴う操作の後に、その団体の行(接続先・状態・チャンネル・停止の予定)の指紋を
  覚えておきます。毎日のバックアップの前に照らし合わせ、違う行・覚えていない行・消えた行の数を監視に渡します
- **スプレッドシートへの書き込み:** `=`・`+`・`-`・`@` で始まる文字列は、数式として扱われないように書きます

## 4. 新しい団体の立ち上げ(R1-c)

FSIF が登録コードを発行し、団体の担当者が団体の Google アカウントでスプレッドシートと GAS を用意して、
レジストリに登録します。最後に、最初の代表が初期設定コードで団体に入ります。

> **招待リンク(R1-d):** メンバー(最初の代表を含む)は、`<サイトの URL>/?org=<団体ID>` から開きます。
> 団体ID は、4.2 の手順 7 の「登録しました」のダイアログと、レジストリの管理画面の「団体」に出ます。

### 4.1. FSIF が行うこと

1. 管理画面(`<サイトの URL>/registry-admin/`)の「登録コード」で、**新しい団体の登録コード**を発行します
   (団体名・担当者の名前とメールアドレス)。コードは発行した画面で1回だけ表示されます。有効期限は14日・1回限りです
2. 団体の担当者に、次の3つを渡します(登録コードは、ほかの2つとは別の連絡手段で渡してください)
   - 登録コード
   - レジストリのウェブアプリの URL(1.2 で控えたもの。`REGISTRY_URL` に入れます)
   - サイトの Google のログインのクライアント ID(GitHub Secrets の `GOOGLE_OAUTH_CLIENT_ID` と同じ値。`GOOGLE_OAUTH_CLIENT_ID` に入れます)

### 4.2. 団体の担当者が行うこと

1. **Google アカウントを用意します。** 団体の運用に使うアカウント(個人の私用アカウントとは分けることをおすすめします)で、
   2段階認証を有効にします。スプレッドシートと GAS は、このアカウントが持ち主になります
2. **スプレッドシートを用意します。** `docs/onboarding.md` の「ステップ 2-1」「ステップ 2-2」のとおり、サンプルのファイルを
   取り込み、サンプルのデータを消します。**「ステップ 2-3 最初の管理者(代表)を登録する」は行いません**(代表は 4.3 の初期設定コードで入ります)
3. **GAS を用意します。** `gas/README.md` の「2. Apps Script のデプロイ」の手順 1〜10 のとおり、`gas/Code.gs` を貼り付けて
   ウェブアプリとしてデプロイします(次のユーザーとして実行: 自分、アクセスできるユーザー: 全員)。デプロイの画面に出る URL(`…/exec`)を控えます
4. エディタの関数の一覧で `setupOhsumi` を選んで実行します(シートの列・団体ID・セッションの鍵・トリガーを作ります。初回は権限の確認が出ます)
5. 「プロジェクトの設定」→「スクリプト プロパティ」に、次を入れます

   | プロパティ | 値 |
   |---|---|
   | `REGISTRY_URL` | FSIF から受け取ったレジストリの URL |
   | `GOOGLE_OAUTH_CLIENT_ID` | FSIF から受け取ったクライアント ID |
   | `OHSUMI_WEBAPP_URL` | 手順 3 で控えた、この GAS のウェブアプリの URL(`https://script.google.com/macros/s/…/exec`) |

   `OHSUMI_WEBAPP_URL` は、デプロイの画面(「デプロイ」→「デプロイを管理」)に出る URL をそのまま入れます。
   `/dev` で終わるもの(エディタで試すための URL)・`/u/1/` などを含むもの(複数の Google アカウントでログインしたブラウザの
   アドレスバーの形)・`/a/macros/<ドメイン>/` を含むもの・`?` や `#` の付いたものは、**レジストリに送る前に断ります**
   (レジストリの側でも受け付けません)

6. **スプレッドシートを開き直します**(再読み込み)。上部に「Ohsumi」メニューが出ます
7. **「Ohsumi」→「レジストリに登録する…」** を選びます。ダイアログに**登録する接続先(この GAS の URL)**が出るので、
   手順 3 で控えた URL と同じか確かめてから、FSIF から受け取った登録コードを入れて「OK」を押します
   (初回は権限の確認が出ます。レジストリへの通信の許可です)
   - 登録できると、**最初の代表の「初期設定コード」がダイアログに1回だけ表示されます。** 控えて、最初の代表になる人に伝えてください
     (有効期限は72時間・1回限り。スプレッドシート・実行ログには残りません)
   - 「応答を受け取れませんでした」と出た時は、少し待ってから**同じ登録コードで**もう一度行ってください。二重には登録されず、
     「使用済み」でも失敗しません(**最初の登録から24時間まで**)。
     送り直しと分かるのは、団体の GAS が登録の前に作ってスクリプトプロパティ(`REGISTRY_PENDING`)にだけ保存した乱数
     (`registerNonce`)が合う時だけです。**使用済みの登録コードを手に入れた人が送っても、共有鍵は返りません**
     (ほかの失敗と同じ「使えなくなっています」で断り、総当たりの失敗として数えます)。
     24時間を過ぎた・`REGISTRY_PENDING` が消えた時は、FSIF に再登録コード(4.4)を発行してもらいます
   - 初期設定コードを控え損ねた・期限が切れた時は、**「Ohsumi」→「初期設定コードを作り直す」** で作り直せます(前のコードは使えなくなります。代表がいる団体では作れません)

### 4.3. 最初の代表が入る

1. **招待リンク**(`<サイトの URL>/?org=<団体ID>`)から Ohsumi を開き、ログイン画面で **「初期設定コードをお持ちの方」** を押して、初期設定コードを入れます(区切りの `-` や小文字でも構いません)
2. 「Google でログイン」を押し、代表になる Google アカウントでログインします。**そのアカウントが代表として団体に登録され、そのまま入れます**
   (コードの確認・代表の登録・ログインは、1回の通信で行います)
3. 以降のメンバーは、代表が Ohsumi の管理画面の「Members」で追加し、同じ画面の**招待リンク**を伝えます
4. 管理画面の「団体」に、登録した団体が出ます(「まだ確認がありません」の印は、団体の GAS が1時間ごとの確認(`checkContractStatus`。1.9)に来ると消えます)

初期設定コードの間違いが10回続いた時は、そのコードは使えなくなります(4.2 の手順 7 の「作り直す」で作り直します)。

### 4.4. 共有鍵が漏れた時・接続先が変わった時(再登録)

レジストリから団体の GAS へ指示を送る入口は作らないため、共有鍵の作り直しは**再登録コード**で行います。

1. FSIF: 管理画面の「登録コード」で種類を **「登録済みの団体の再登録コード」** にし、団体を選んで発行します(14日・1回限り。その団体にだけ使えます)
2. 団体の担当者: 「Ohsumi」→「レジストリに登録する…」で、再登録コードを入れます
3. レジストリが新しい共有鍵を作り、団体の GAS に保存されます。**古い共有鍵は、この時点で使えなくなります。**
   接続先の URL(`OHSUMI_WEBAPP_URL`)が変わっていれば、新しい URL に変わります
4. 操作の記録に「団体の再登録(共有鍵の作り直し・接続先の変更)」が残ります(鍵の世代が1つ増えます)

新しい団体の登録コードで、登録済みの団体を登録し直すことはできません(「登録済みです」と出て、コードは使われません)。

### 4.5. すでに動いている団体の登録(テスト環境など)

すでにメンバーと代表がいて、ログインして使っている団体を、あとからレジストリに登録する手順です。
**今の代表・メンバー・ログイン(ログイン中の人のセッションを含む)・シートの中身は変わりません。**

**対象:** このリポジトリの `gas/Code.gs`(ID トークンでのログインに対応した版。スクリプトプロパティに `ORG_ID` と
`SESSION_SIGNING_KEY` があるもの)で動いている団体です。

> **FSIF が使っている Orbit について:** Orbit の GAS は、`FSIFofficial/Orbit` の `gas/Code.gs`(Ohsumi から分かれた以前の版)で、
> 団体ID(`ORG_ID`)・ID トークンでのログイン・「Ohsumi」メニューがありません。**この手順では登録できません。**
> Orbit を登録するには、先に Orbit のスプレッドシートを Ohsumi の GAS に移す必要があります(この手順の範囲外です。
> `FSIFofficial/Orbit` のリポジトリは変えません)。

登録で起きること・起きないこと:

| | |
|---|---|
| 増えるもの | スクリプトプロパティ `REGISTRY_SHARED_KEY`・`REGISTRY_KEY_GEN`・`REGISTRY_REGISTERED_AT`(と、手で入れる `REGISTRY_URL`・`OHSUMI_WEBAPP_URL`)、スプレッドシートの「Ohsumi」メニュー、レジストリの Orgs の1行 |
| 変わらないもの | `ORG_ID`(レジストリにはこの団体ID で登録されます)・`SESSION_SIGNING_KEY`・`SESSION_KEY_ID`(ログイン中の人はそのまま)・メンバー・役職・シートの中身 |
| 初期設定コード | **代表がいる団体では作りません**(登録のダイアログにも出ません)。「初期設定コードを作り直す」も、代表がいれば断ります |
| ログイン | 今のメンバーは、これまでどおり入れます(ログイン画面の「初期設定コードをお持ちの方」は使いません。コードを入れて来ても、今のメンバーのまま入ります)。メンバーでない人がコードを入れて来ても、コードが作られていないので断ります |

手順:

1. **代表がいることを確かめます。** Members シートの `role` 列に、代表(最上位の役職)の人が1人以上いることを確かめます。
   Ohsumi の画面で、代表のアカウントでログインできることも確かめます
2. **GAS を新しい版にします。** Apps Script エディタで `Code.gs` を貼り替えて保存します。
   **デプロイの前に**、エディタの関数の一覧で `setupOhsumi` を選んで実行し、権限の確認が出たら許可します
   (この版で、スプレッドシートにメニューを出す権限が増えます。先に許可しておかないと、ウェブアプリが権限の確認を待って止まります。
   `setupOhsumi` は、既にある `ORG_ID`・鍵・データの値を変えません)
3. 「デプロイ」→「デプロイを管理」→ 今のウェブアプリの編集(鉛筆)→「バージョン: 新バージョン」でデプロイします。
   **新しいデプロイは作りません**(URL が変わり、今使っている接続先とずれます)
4. FSIF: 管理画面で、その団体の名前で**新しい団体の登録コード**を発行します(4.1)
5. スクリプトプロパティに `REGISTRY_URL`(レジストリの URL)と `OHSUMI_WEBAPP_URL`(今のウェブアプリの URL。
   「デプロイを管理」に出る `…/exec`)を入れます。**ほかのプロパティは変えません**
6. スプレッドシートを開き直し、「Ohsumi」→「レジストリに登録する…」を選びます。ダイアログの URL が、今のウェブアプリの URL と同じか確かめてから、
   登録コードを入れます
7. 「登録しました」のダイアログに**初期設定コードが出ないこと**を確かめます。
   **もし初期設定コードが出たら、代表がいると判断できていません。** そのコードは誰にも伝えず、Members シートの代表の `role` を
   確かめてください(代表が見つかる状態になれば、そのコードは使えません。72時間で切れます)
8. 代表・メンバーが、これまでどおりログインできることを確かめます。管理画面の「団体」に、その団体が出ることも確かめます

## 3. バックアップ

- 毎日午前3時台に、スプレッドシートを「Ohsumi レジストリのバックアップ」フォルダにコピーします
  (名前: `Ohsumi レジストリ バックアップ yyyy-MM-dd`)
- **コピーは Secrets(共有鍵)を含みます。** 作ったコピーから編集者・閲覧者を外し、リンクの共有も「制限付き」にします。
  見られるのはレジストリのアカウントだけです
- 30日より古いコピーは、同じ処理でゴミ箱へ移します(ゴミ箱からは Google ドライブが30日後に消します)
- コピーには Apps Script も複製されますが、**コピーの Apps Script はデプロイしないでください**

### 戻し方

1. バックアップのフォルダから、戻したい日のコピーを開きます
2. 壊れたシートを、コピーのシートで置き換えます(コピーの該当シートの中身を、元のスプレッドシートの同じシートに貼り付けます)
3. 元のスプレッドシートの Apps Script で `setupRegistry` を実行し、シートと保護を確かめます
4. Orgs を戻した場合は、記録の無い変更として監視に知らされます。AuditLog に、戻したことと理由を管理画面から記録します(R1-b 以降)

**テスト環境で一度、戻す手順を試しておいてください。**
